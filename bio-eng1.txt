1. What is Git?
Git is a tool that helps developers keep track of changes they make to their projects. It allows us to save different versions of our work so that we can go back to an earlier version whenever something goes wrong.
From what I have learnt, Git makes working on software projects easier, especially when working with other developers. Instead of everyone making changes to the same files and causing confusion, Git allows each person to work on their own part of the project and combine the work later.

2. Version Control and Its Benefits

Version control simply means keeping track of changes made to files in a project over time. It helps developers know what has changed, who made the changes and when they were made.

Some benefits of version control include:

It helps us keep track of changes made to our projects.

It allows us to return to an earlier version if we make a mistake.

It makes it easier for developers to work together.

It reduces the chances of losing important files or work.

It helps us know who made specific changes.

It allows different developers to work on separate features without disturbing one another.

3. Common Git Commands and Their Uses

During our practical sessions, I learned several Git commands and how they are used when working on a project.

Some of the commands include:

git merge: Used to combine independent lines of development from two different branches into a single branch.

git clone: Used to download an existing repository from GitHub to our computer.

git status: Helps us check the current state of our files and see which changes have been made.

git add .: Used to prepare all changed and new files for committing.

git commit -m "message": Used to save our staged changes with a short description of what we have done.

git push: Used to upload our committed changes from our computer to GitHub.

git pull: Used to get the latest changes from GitHub and update our local project.

git fetch: Used to check and download updates from the remote repository without automatically merging them.

git branch: Used to view or create branches in a repository.

git switch: Used to switch from one branch to another.

git merge: Used to combine the work done on different branches.

git log: Used to view the history of commits made in a repository.



4. Git Repositories

A Git repository is simply a project folder that Git manages and keeps records of. It contains the project files as well as information about the changes made to them.

There are two main types of repositories:

Local Repository:

A local repository is the copy of a project stored on our own computer. This is where we create files, edit our work, create branches and make commits.

Remote Repository:

A remote repository is a copy of the project stored on an online platform such as GitHub. It allows other team members to access the project and contribute their own work.

5. Branching in Git

Branching is one of the Git features I found very useful during our team collaboration exercise. It allows developers to work on different parts of the same project without making changes directly to the main branch.

For example, in our practical assessment, we created three branches:

master: This is the main branch where the final work of the team is brought together.

eng_1: This is the branch assigned to Engineer 1.

eng_2: This is the branch assigned to Engineer 2.

Each engineer works on their assigned branch and pushes their contribution to GitHub. This makes it easier for everyone to work independently without interfering with another person's work.


6. Merging in Git

Merging is the process of bringing changes from one branch into another. It allows developers to combine their individual contributions into one complete project.

For example, after Engineer 1 finishes their work and pushes it to GitHub, the Team Lead can merge that work into the master branch using:

git merge eng_1

The Team Lead can then bring in Engineer 2's contribution using:

git merge eng_2

From this exercise, I understand that merging is important because it helps bring everyone's work together so that the team can have one complete and updated project.


7. Merge Conflicts and How to Resolve Them

A merge conflict happens when Git finds changes that it cannot automatically combine. This usually happens when two developers make different changes to the same part of a file.

When this happens, Git needs the developer to decide which changes should remain or how both changes should be combined.

To resolve a merge conflict, I would follow these steps:

Run git status to identify the file causing the conflict.

Open the affected file using an editor such as Nano.

Look for the sections marked by Git as conflicting.

Review both versions and decide what the final content should look like.

Remove the conflict markers added by Git.

Save the corrected file.

Use git add to stage the resolved file.

Complete the merge by committing the changes if Git requires it.

9. My Understanding of the Git and GitHub Workflow

From our team collaboration practical, I have come to understand how Git and GitHub work together when developers are working on the same project.

The process starts with the Team Lead creating a repository on GitHub and cloning it to their computer. The Team Lead then creates separate branches and assigns one to each engineer.

Each engineer clones the repository, switches to their assigned branch and works on their own task. After completing the work, they use git add to stage their files, git commit to save their changes and git push to upload their contributions to GitHub.

Once both engineers have pushed their work successfully, the Team Lead retrieves the latest updates and merges the two branches into the master branch.

Finally, the Team Lead pushes the updated master branch to GitHub so that the repository contains the completed work from both engineers.

This process has helped me understand how developers can work together on the same project while keeping their contributions organized.
